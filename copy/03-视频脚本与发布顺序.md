# 视频脚本与发布顺序

## 90 秒横版介绍：学习笔记 × 技术文档

使用 07 横版封面。展示部分用真实录屏，AI 海报只作为封面、过场或结尾，不当作操作成功的证据。当前没有附已经录制的视频。

| 时间 | 画面与操作 | 口播 / 字幕 |
|---|---|---|
| 0–6 秒 | 一个干净的编辑窗口，开始写“今日学习笔记” | 写笔记和记代码，有时只需要打开一份文档。 |
| 6–20 秒 | 输入一个小标题、正文和引用，展示同一区域的排版 | 我做了手书 Tekaku。在同一页边写边呈现，不需要一直切换编辑和预览。 |
| 20–32 秒 | 通过斜杠菜单插入待办，写两件事，勾选一件 | 课程重点、读书摘录、待办清单，都可以放在这张页面里。 |
| 32–48 秒 | 插入代码块，选 Python 或 JavaScript，输入一小段自己的代码 | 写项目笔记时，也可以保留代码高亮，把文字和代码一起记下来。 |
| 48–60 秒 | 在应用内打开另外两份样例文档，切换标签，再回到第一份 | 几份文档，用 Tab 切换。学习记录和技术文档，各自保留内容。 |
| 60–70 秒 | 展开右侧大纲并定位到标题；简短展示皮肤设置 | 长一点的内容，可以用大纲定位。外观也能调成自己习惯的样子。 |
| 70–82 秒 | 手动保存到测试目录，展示文件名；录屏中按实际结果操作 | 文件留在自己选择的位置。Windows 便携 ZIP 约 1.9 MB，使用系统 WebView2。 |
| 82–90 秒 | 干净结尾页或 01 品牌图，出现“公开测试中” | 项目还在公开测试。想看支持范围与已知问题，或者给我一个真实需求，都可以到项目说明里看看。 |

画面里的 1.9 MB 必须标注“Windows ZIP 下载包”，不写成内存、启动耗时或性能对比。需要安装系统运行时的情况不要剪成“零依赖”。

不要演示一个没有实现的跨端同步动作。若加入 Android 过场，单独标“Android 版 · 各自本地保存”，使用原始手机版截图或手机真实录屏。

## 30 秒竖版剪辑思路

- 0–4 秒：02 的主题——“写下，即呈现”。
- 4–12 秒：真实录屏输入标题、待办和正文，只展示一个编辑区域。
- 12–20 秒：记一段代码，再切换一份文档。
- 20–26 秒：回到文档，保存到本地。
- 26–30 秒：手书 Tekaku / 学习笔记 × 技术文档 / 公开测试中。

用实际录屏的清晰局部作为主体，不靠反复闪烁、系统弹窗或复杂转场增加刺激。录屏时只使用自己的样例内容，隐藏个人目录、通知和私人文档。

## 图文发布顺序

通用首发：01 品牌 → 02 输入体验 → 03 多 Tab → 04 代码内容 → 05 Android → 06 下载体积。

学生场景版：02 → 01 → 03 → 04 → 05。正文先写如何记录课程内容，再讲功能。

程序员场景版：04 → 03 → 02 → 06。正文先写 README、开发笔记和代码片段，再讲技术实现。

Android 专场：05 + 原始手机版界面截图。不要让 Android 受众把 Windows ZIP 的 1.9 MB 当成 APK 大小。

## 首轮标题测试

同一个平台先分别自然发布两种不同场景内容，留出观察时间，不复制刷屏。两条都不使用无法证实的结论：

A：我做了个简洁的 Markdown 编辑器（产品与笔记场景）

B：给项目笔记做了个轻量 MD 编辑器（开发者场景）

比较有效提问、项目访问和主动反馈的差异。账号基础、发布时间与内容形式都会影响结果，不把两条内容的差异直接归因为标题或图片。

## 发布时附上的事实说明

Windows 版需系统 WebView2；约 1.9 MB 是 ZIP 下载体积。Android 版需较新的系统 WebView；APK 约 235 KB。两端不提供自动同步。当前 Windows 安全拦截报告仍在核查，具体限制与验证范围见项目说明。按平台当时的要求标注 AI 辅助宣传设计。
